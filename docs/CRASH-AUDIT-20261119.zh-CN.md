# 2026-11-19 本机崩溃日志复核

本轮确认 eNSP 主界面、PCServer 和 VBoxServer 存在不同的异常记录，并修复融合插件的原生日志诊断遗漏。**本次完成的是历史日志分析和诊断代码修复；eNSP 原生崩溃根因与恢复后的稳定性仍待验证。** 所有下述现场时间均为北京时间，DSH 原始 UTC 时间已换算。

## 取证范围和计数方法

读取 `%LOCALAPPDATA%/eNSP/Log`、安装目录 `plugin/pc_client_server/log`、Windows Application 事件、DSH 桌面宿主异常日志及 `%USERPROFILE%/.dsh/sessions`。共解析 344 份 DSH 连续 Zstandard 会话，未跳过文件；原生日志抽取 380 份，其中 PCServer 日志 356 份，按 BOM 正确读取 UTF-16LE。分析大于 32 MiB 的会话时逐帧处理，没有放宽产品日志导出的 32 MiB 限额。

Windows 筛选时间为 2026-11-01 起，实际 eNSP 异常发生于 11-09 至 11-18。采集的相关事件共 329 条；其中明确以 eNSP 为应用的事件 1000 有 100 条。按应用名、PID、进程创建时间合并后，对应 73 个进程实例。**这是出现异常记录的实例数，不等于已经证明的 73 次独立终止。** 同一实例可能先后报告不同异常，事件 1001 还可能反复提交旧报告，不能将所有事件相加作为崩溃次数。

DSH 直接以 `ensp_*` 名称登记的调用原有 1,220 条，按 callId、时间、工具名去除分叉会话继承记录后为 1,135 条，均找到结果。另提取 1,872 条参数提及 eNSP/相关路径的其他工具调用，包含 `run_code` 内部调用；这些是引用记录，不能作为内部实际调用次数。直接调用的计数不代表全部插件使用量。

本机 eNSP 注册表名称为 V1.3.00.100；客户端字符串版本为 1.2.00.510，而固定数值版本为 **1.2.0.500**，与事件一致。不能仅凭字符串差异断言已经升级到不会崩溃的新二进制。

## 原生日志反映的恢复缺口

11-09 至 11-19 的样本包含 669 条资源配置上传失败、249 条 `Failed to put vrpcfg.zip`、30 条设备启动失败及 130 条进程退出等待失败。`GetVBoxFileListenPort failed` 有 1,200 条重试记录；多条重试可能属于同一次操作，不应算成 1,200 次独立故障。共享日志未提供足够设备身份，不能据此直接归因某台防火墙或交换机。

最近两天默认采样的四份共享日志中，原诊断规则可匹配 83 条，但输出仅列最后 80 条；新增规则后识别 **148 条**，其中新增识别的 **65 条**为配置文件传送失败 38 条、设备启动失败 15 条、进程退出等待失败 12 条。同步失败总数为 121，另有启动失败 15、退出等待失败 12。它们是历史事件样本，不代表此刻每台设备都在失败。

原生 `[ERROR] ... Succeed in connecting.: 0.` 会出现在成功消息上；`Avaliable bytes can be read from pipe: 0`、socket 10004/10038 也可能出现在退出清理阶段。本轮没有仅凭 ERROR 标签、空管道或退出消息建立新的崩溃结论。

PCServer 的 UTF-16LE 日志另外记录了 HttpClient 获取目标地址失败、连接失败和 ping 失败；这些业务失败无法代替 UDP 插件崩溃栈。现有在线 `ensp_console_diagnose` 的采样范围仍是共享日志及匹配 UUID 的 USG VM 日志，不包含 Windows 崩溃报告和 PCServer 日志，返回值已明确说明这一边界。

## DSH 日志和安装副本

直接工具调用中有 71 条外层错误，187 条包含结构化 `ok:false`；其中 159 条外层未标错。两类集合有重叠，不能相加为失败总数；历史正文还可能是嵌套字符串，统计仅是可明确识别的下限。可见旧版本的冻结参数 `path` 赋值异常、仅 `#` 控制台超时、未知交互、窗口不存在、鼠标位置变化后取消和控制台未就绪。当前源码已包含冻结参数、结果外层适配及部分交互修复，不重复把历史故障登记为现版本新增缺陷。

11-11、11-14、11-16、11-17 的五份 DSH host 异常日志均记录退出码 **1073807364 / 0x40010004**。微软将其命名为 DBG_TERMINATE_PROCESS；这些日志没有提供可以证明 eNSP 插件抛出未捕获异常的堆栈。日志尾部存在模型目录请求 401，但该信息本身不证明是宿主退出原因，也不证明由谁发起终止。[微软状态码定义](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55)

桌面安装副本与源码均标 1.1.3。修改前核对的 topology、bridge、console-diagnostics 和 reliability-tools 文件一致；安装副本尚不包含源码中的未发布 scenario-lab。该差异符合仓库已经声明的未发布增强，不能当作本轮崩溃根因。修复后源码的诊断文件已与安装副本不同，**本轮未更新桌面安装副本，也没有证明运行中 DSH 已加载本轮补丁**。

## 本轮修复与验证

- 补识别原生配置传送、文件传输端口获取、启动和退出等待失败，INFO 级别失败同样进入诊断。
- 日志读取支持严格 UTF-8 检测后回退 GB18030，保留中文；有界尾部读取丢弃不完整首行，使用实际读取字节数。
- 区分类别缺失、目录为空、日志轮转/读取失败和无匹配错误；缺少所需证据时返回 `INSUFFICIENT_LOG_EVIDENCE`，列出不可用来源。
- 保留最多 80 条详细发现，同时返回总数、按类型计数和省略数量；时间采用文件名日期及日志本地时钟，明确未验证时区和时钟，mtime 不冒充事件时间。
- 新增五项回归，覆盖真实失败文本、中文解码、尾部边界、部分日志发现和工具入口、缺失 USG VM 日志。328 项 Node 测试及 24 项 MCP 冒烟通过；插件检查和打包离线安装检查通过。

DSH 默认隔离检查尝试启动安装的 Electron 可执行文件时返回 `spawnSync EACCES`。随后使用当前已解包安装目录中的真实 DSH 模块，在 Node `--expose-internals` 下完成兼容性门禁、19 工具注册、原生执行器错误传播和卸载检查，结果通过。它是宿主模块级验证，不是 Electron 启动验证或运行中桌面会话验证。

## 后续优先事项

1. 取得下一次原生异常的可读 dump/调用栈，同时记录进程创建时间、工具 callId、GUI 动作和实际加载的兼容层。现有部分 WER 目录访问受限；本轮以可读 Application 事件为主，没有更改 ACL 或启用系统抓取配置。
2. 对配置上传/下载失败完成单设备闭环：工程检查点、真实 VRP、实际 startup/current/saved 对比、正常停止和同路径重开。端口监听、文件存在、脚本没有抛错均不足以证明配置已加载。
3. 统一 `run_code` 验收结果：检查返回 `ok`、设备结果和断言状态，保留错误；日志中已有 `catch { return '' }` 及只按调用未抛异常计数的包装，存在掩盖失败的风险。本轮没有把这些历史临时脚本算作插件源码，亦未擅改用户的实验结论。
4. 经过独立部署核验后再宣称补丁在桌面生效；按实际 root 和构建 fingerprint 核对。原生崩溃、数据面和长期稳定性分别复验，不能由 328 项软件测试推导通过。
