# 1.1.4 候选：配置资产与完整失败证据

日期：2026-11-20。源码与本地候选包版本为 1.1.4，npm 未发布。19 个工具、2 个技能，peer 继续精确支持 DSH tools rc.1/rc.3/rc.5，开发锁文件使用 rc.3。本候选包含此前 M1/M2/M2.1 增强；旧版本安装与现场验收结论保留原始构建范围。

## 三项修复

1. **AC/AP 配置识别**：检查唯一的 vrpcfg.zip、vrpcfg.cfg 或 flash.efz。ZIP 继续验证目录边界、膨胀上限与 CRC；AC 的版本头加有效配置正文允许不含 sysname。多个候选为 ambiguous，缺少 AC/AP 资产为 persistence_unverified，未知不会计为成功。仍不证明活动启动指针或冷加载。
2. **检查点完整性**：统一建立拓扑和全部设备目录的配置资产清单，包括 vrpcfg.zip、全部 .cfg、flash.efz、PC.xml 与空目录。逐文件大小/SHA256 及源复制前后、目标三方一致，才确认 assetCopyVerified；源变化或不完整配置保留失败。备份范围不含 VM 磁盘和完整运行态。
3. **完整错误证据**：ensp_logexport 可按 operation_id 或 call_id 精确筛选，保留嵌套结构化失败、跳过命令、执行元信息和原始外层错误；原始物理行号保留。先跨记录收集凭据再脱敏，不覆盖目标、不改原会话。只有元数据时明确证据不足，不重建响应。DSH 外层错误同时带 operation_id 与导出指引，便于从通用错误定位正文。

## 用法

在 DSH 中调用 ensp_logexport，指定 source 为实际本地 JSONL/Zstandard 会话，destination 为工作区内的新 JSON 文件，operation_id 为错误消息或 execution 中的操作 ID。也可改用完整 call_id，包含 :ptc:N 等后缀。两种筛选互斥，不能同时提供。

目标父目录须已存在且位于当前工作区；source 允许只读访问工作区外日志。无筛选时维持脱敏 JSONL 行为，有筛选输出结构化 JSON。Zstandard 需要 Node 22.15+，其他能力继续支持 Node 20+。先确认 structuredResults 与 evidenceLevel，不能将“导出成功”当作原设备操作成功。
