# 1.1.0 更新说明与迁移

状态：**GitHub 预发布已发布，npm 未发布，2026-11-12**。GitHub 预发布 Release（tag `v1.1.0`）已创建；npm 包 `dsh-ensp-fusion@1.1.0` 尚未发布。本文件同时是 Release 正文的基础。完整变更见[更新日志](../../CHANGELOG.md)。

## 本次更新解决什么

插件从基础设备操作扩展为带预检、业务断言、变更保护和故障收尾的实验工具。统一16个工具，继续由DSH、MCP和CLI共用实现；新增验收与环境诊断命令，不额外增加MCP工具数量。

| 工作流 | 更新内容 | 使用边界 |
| --- | --- | --- |
| 配置前检查 | inspect版本/配置/接口/路由/LLDP；历史固件识别；离线diagnose | 历史匹配不等于当前健康，UNKNOWN不是通过 |
| 拓扑核对 | 双向LLDP、时间戳、名称映射、拓扑接口映射及排除端点 | 未知接口不猜测，PC/Cloud等不以LLDP验收 |
| 设备变更 | 跨进程端口锁、dry_run、快照、日志、保存确认、guard恢复 | 失败可能已有配置生效；不自动猜反向命令 |
| 正式验收 | 整计划预检、独立证据目录、反序清理、持久清理台账与recover | 强杀/断电不能保证finally；恢复依赖完整journal、认证与guard |
| 业务检测 | 宿主HTTP/DNS/FTP/TCP，原生服务预检/恢复组件，稳定性与隔离评估 | 宿主与客体证据分别判断，服务启动按钮不能代替协议结果 |
| GUI自动化 | 显式窗口定位、DPI页签、标准列表选择、终端发现、启动就绪 | 依赖Windows交互桌面，鼠标保护取消须检查现场 |
| 文件可靠性 | 原编码保持、GB18030/UTF-16支持、端点参数及端口预检 | 不覆盖已有输出，不迁移或修复第三方设备镜像 |
| 工程交付 | doctor、Python版本清单、固定peer依赖、离线安装及打包验证 | 未发布到npm（GitHub侧为预发布），完整DSH宿主尚无同等级实跑验收 |

## 新入口

源码中的命令：

```powershell
node bin/ensp-fusion.mjs tools
node bin/ensp-fusion-doctor.mjs --help
node bin/ensp-fusion-accept.mjs --help
```

验收命令包括：

- `run <plan.json> [workspace] [output-directory]`：执行显式计划。
- `status <run-directory>`：读取原结果及中断/清理状态。
- `recover <run-directory> <original-plan.json> [workspace]`：核对原计划后恢复未完成清理。
- `assess <business-evidence.json>`：只读评估提供的稳定性或隔离证据，不发流量。
- `usg-health <resource-samples-and-limits.json>`：只读评估资源样本，不能认证吞吐。
- `services-check <manifest.json> <topology.topo> [workspace]`：仅服务恢复前预检，输出`PREFLIGHT_ONLY`。

## 从1.0.0迁移

1. Node要求20及以上。保留锁文件，运行`npm ci --ignore-scripts`；peer依赖为`@deepseek-ai/dsh-tools@0.0.1-rc.1`和`@deepseek-ai/schemastery@3.19.0`。
2. 工具发现应读取实际schema。工具数从12增至16；不能把所有返回都按同一种结构解析。新增融合工具的`data`为JSON字符串，原基础工具维持原格式。
3. `ensp_lldp`提供`links`或`topo_path`之一；观测含真实`collected_at`。默认检查双向及五分钟新鲜度，证据缺失为INCONCLUSIVE。
4. 服务计划显式设置`vantage:host`。验收eNSP客体时另行保留端点、路径、协议及内容证据，不能用宿主机结果替代。
5. 正式变更先`dry_run:true`，再提供`change_dir`与已核对的`recovery_commands`。恢复调用只引用原`recover_from`记录，不传新目标或覆盖命令。
6. 既有含缺值、重复参数或非法IP/MAC的Client/Server拓扑可能被新预检拒绝；先备份并修复副本，不能靠绕过预检发布损坏工程。
7. 原生中文拓扑不强制另存UTF-8。编辑保持原编码，非ASCII新生成文件使用GB18030；目标字符无法往返时拒绝写入。
8. 验收改为检查完整数量/状态，保留首轮、冷启动及失败记录。不能用含`0.00% packet loss`的子串独立证明零丢包。

## 已完成的验证

截至2026-11-12，本机291项Node测试、24项MCP冒烟、打包离线干净安装、打包CLI/MCP及插件检查通过。环境为Windows / Node22.19.0 / eNSP1.2.0.500；Python依赖见[版本清单](../../requirements-windows.lock.txt)。测试结果是本机限定环境证据，不是所有版本保证。

GitHub准备新增README导航、完整更新日志、已知问题、贡献及发布指南、`check:release`离线检查，并增强打包文档完整性验证。本轮复跑上述软件检查通过，发布检查的仓库内链接与候选文件检查通过；2026-11-12 已创建 GitHub 预发布 Release；npm 尚未发布。

- 原生Client→Server的HTTP200正文、DNS应答、FTP226与下载哈希实测通过。
- 四台园区Server独立修复副本初始化、地址和中文显示通过；原园区交付文件未覆盖。
- USG两轮0.5/2/8 Mbps、1/8/32 UDP流，每档25秒，USG前后计数一致；使用现场端点隧道合成帧，不是客体应用确认。
- 约32分钟有限浸泡、设备/应用重开和两轮备用链路恢复有历史证据；切换过渡存在丢包，原生服务需显式清单恢复。

## 发布时必须保留的限制

**整体业务总验收仍FAIL。** 冷ARP丢包、USG之后的端到端瓶颈、指定S5700 VRP5.110/V200R001C00的TCP拒绝失败尚未修复；不能宣传全园区已建成或全部业务通过。

尚未验收200 Mbps、TCP连接容量、最大转发能力、24/72小时、无人值守Windows启动恢复、园区全业务及全部固件组合。原始pcap、截图、设备配置、账号和本机路径不随插件仓库发布；仓库提供脱敏结论摘要，不能仅凭摘要独立复算现场结果。
