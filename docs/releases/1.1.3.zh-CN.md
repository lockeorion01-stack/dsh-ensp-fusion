# 1.1.3：DSH 0.2.2-rc.3 兼容修复

日期：2026-11-14。本版本继续提供 19 个工具、2 个技能，包含 1.1.2 的全部可靠性修复。npm 尚未发布。

## 问题与修改

1.1.2 精确要求 `@deepseek-ai/dsh-tools@0.2.2-rc.1`。DSH 升级到 0.2.2-rc.3 后，宿主在载入插件前拒绝这个声明；该警告本身不代表已经发生崩溃或数据丢失。

1.1.3 将 peer 声明改为 `0.2.2-rc.1 || 0.2.2-rc.3`，源码锁文件使用 rc.3 及匹配的 DSH 依赖。`@deepseek-ai/schemastery` 仍为 3.19.0。范围只覆盖已核验的两个版本，没有使用通配符、宿主豁免或修改宿主的版本判定。

`check:dsh` 使用实际桌面宿主的兼容性函数，检查 rc.1/rc.3 可接受、rc.2/正式版/未来预发布不可接受，并确认旧 1.1.2 清单在 rc.3 下会被拒绝。它还挂载插件、注册工具/技能和系统提示，通过原生执行器检查拓扑生成/读取、失败外层和卸载。

本轮实机验收还修复两处工程资产检查假阴性：交换机配置后尾随完整 sysinfo ZIP 时查找最近配置载荷，损坏/截断仍拒绝；USG 唯一自定义 `.cfg` 可检查，多个候选保持歧义，检查点保留全部受界配置。磁盘内容仍不能证明活动启动指针。

## 升级

从完整源码执行：

```powershell
npm ci --ignore-scripts
npm test
npm run check:plugin
npm run check:dsh
npm run test:package
npm run check:release
npm pack --ignore-scripts
dsh plugin --profile desktop add "C:/tools/dsh-ensp-fusion/dsh-ensp-fusion-1.1.3.tgz"
```

替换包路径和 profile 为实际值。保留原 profile 与旧插件副本。安装失败时先看具体依赖错误；如果其他插件的仓库失效，不应通过关闭兼容性检查或覆盖整个 profile 处理。

使用宿主支持的插件管理开关或重启方式加载新版本，然后通过 `ensp_status` 检查 `build.version`、`fingerprint`、`root` 和 `loadedAt`。安装文件更新、插件详情中的磁盘 README 和隔离进程检查都不能单独证明旧运行会话已重载。

维护者可在完整源码目录执行 `npm run check:dsh -- --plugin-root <实际安装目录>`，检查该副本是否能在真实宿主服务中加载。该命令不发送模型请求，不打开 eNSP，不修改用户 profile。
