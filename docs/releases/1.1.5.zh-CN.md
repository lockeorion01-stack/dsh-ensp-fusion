# dsh-ensp-fusion 1.1.5 候选

批量 `ensp_cli` 的顶层 `system_view` 和 `save` 作为各设备的默认值，设备条目可显式覆盖为 true 或 false。预览与执行使用同一份解析结果。

`ensp_logexport` 在原始记录中精确匹配操作或调用 ID，并用全会话收集的凭据对输出脱敏。常见 SDK 口令说明可以与真实命令区分，短口令及其回显也会遮盖。标识符本身含实际凭据时，仍可用原始 ID 选择，导出中的标识符会脱敏。

## 修正已有工程的标签覆盖

在 DSH 中可直接要求“修正 campus.topo 的标签覆盖，输出为 campus.labels.topo”。绘图 skill 调用现有的 `ensp_topo`。

| 动作 | 结果 |
| --- | --- |
| `layout-inspect` | 估算设备图标、名称、端口、文字标注和连线间的冲突 |
| `layout-preview` | 返回移动提议、前后冲突计数及无法识别的几何字段 |
| `layout-apply` | 需要新的 `.topo` 输出路径，写入可编辑副本 |

```json
{"action":"layout-apply","topology_path":"campus.topo","out_path":"campus.labels.topo"}
```

设备标识、连线端点、槽位、终端配置及扩展字段参与非布局内容哈希校验。端口布局依赖原生锚点及偏移字段。原生字体、显示比例和客户端打开时重算的坐标可能影响实际效果，应结合当前工程的全图及核心区截图查看。副本是拓扑文件，配置资产仍属于原工程目录。
