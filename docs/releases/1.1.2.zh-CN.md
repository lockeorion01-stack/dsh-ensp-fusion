## 新工具用法

`ensp_project` 的 action 为 inspect/checkpoint/compare，输入 topology_path；expected 或 expected_file 提供“设备名 → 必须存在的配置子串数组”。checkpoint 的 backup_dir 必须是项目外的新目录，compare 使用 manifest_path。

它只备份 `.topo` 和已支持的配置资产，不复制设备磁盘。`flash.efz` 解析支持 eNSP 容器中最后完整、长度有界的 ZIP 配置载荷，并验证 CRC；不解析挂载文件系统指针，因此可能仍是历史内容。必须用 expected 检查当前基线。该工具始终返回 reloadVerified:false，重开恢复需独立 GUI 和 CLI 证据。完整工程迁移另做备份。

`ensp_console_diagnose` 需要 topology_path、device，默认只读日志；probe:true 单次读取提示符及 display version，timeout_ms 为 100–15000。native_log_root 可指向本机 eNSP 日志目录。共享日志不直接归因某设备，无可读日志时返回证据不足。

`ensp_logexport` 需要 source 和新 destination。支持 JSONL 与连续 Zstandard 帧，后者需要 Node 22.15+ 原生支持；其他工具仍支持 Node 20。导出会将嵌套 JSON 字符串解析为对象以脱敏，输出结构可能改变。先遍历全会话收集已知凭据和应答值，再遮盖先前回显。32 MiB 输入/解压上限、100000 条记录/帧上限；非法 JSONL 拒绝导出，不退回原文复制。未知自由文本、截图和旧日志仍需审查。

本地凭据 JSON 用 credential_ref 作键，条目仅允许 username/password/passwords/new_password。根级 credential_file 适用于 devices/ready_devices，不能与同目标的明文凭据混用。commands_file 是非空命令数组。CLI 路径相对工作区；labtest 计划引用文件相对计划目录，topology_base 只控制拓扑路径。

命令对象示例（应答值可能被宿主记录，敏感命令请放 commands_file）：

```json
{"cmd":"rsa local-key-pair create","expected_view":"configuration","replies":[{"expect":"Input the bits in the modulus[default = 512]:","reply":"2048"}]}
```

## 安装与运行版本核对

从完整源码执行 `npm ci --ignore-scripts`，完成 `npm test`、`check:plugin`、`check:dsh`、`test:package`、`check:release` 后本地打包。保存旧安装副本，将新包安装到目标 profile，按宿主支持的方式重载插件。

在目标会话调用 ensp_status 核对 version、fingerprint、root、loadedAt。源码及安装副本指纹应一致；旧会话未重载不能声称新代码已运行。`npm run check:dsh -- --plugin-root <安装目录>` 可在隔离进程用真实宿主服务检查该副本，它不证明完整桌面模型会话热加载。

插件无法修复交给其实现之前的截断 JSON。SDK 回归已覆盖拒绝此输入且不进入桥/设备操作；不为畸形参数猜补内容或重放有状态动作。
