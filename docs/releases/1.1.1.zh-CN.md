# 1.1.1 DSH兼容性修复

2026-11-12，兼容性修复版本，目标宿主为**DSH 0.2.2-rc.1**。本说明对应1.1.1仓库源码，npm尚未发布；既有GitHub `v1.1.0`预发布仍是旧版，升级请使用1.1.1源码生成的包。1.1.0功能及历史实机结果见[原发布说明](1.1.0.zh-CN.md)，全部软件变更见[更新日志](../../CHANGELOG.md)。

## 原因与修改

1.1.0将peer依赖精确固定为`@deepseek-ai/dsh-tools 0.0.1-rc.1`。DSH 0.2.2-rc.1在载入前会将此声明与自己的运行版本比较，因此拒绝载入。这是插件兼容性判定，与eNSP设备启动或USG性能无关。

1.1.1将该peer及锁文件对齐到`0.2.2-rc.1`，保留`@deepseek-ai/schemastery 3.19.0`，同时更新包/MCP版本。没有添加`engines.dsh`来覆盖peer判定，没有使用通配依赖、强制安装或风险豁免。原有defineTool、tools.register、skills.register和systemPrompt.section调用经目标SDK及本机宿主验证可用。其他DSH版本仍需独立验证。

README同步重写，按项目用途、快速开始、三种接入方式、16工具和验证结果组织，明确源码安装与打包安装方法。部署、贡献、验收及GitHub发布文档同步更新，保留原有业务失败和未测范围。

## 升级

源码方式：取得本次完整1.1.1源码，在插件目录执行：

```powershell
npm ci --ignore-scripts
node bin/dsh-ensp-mcp.mjs --version
npm run check:dsh
```

版本应显示`1.1.1`。已有`link:`依赖指向此源码目录的profile，在依赖安装后重新加载插件；若仍提示1.1.0，核对实际加载路径及缓存的旧包。profile链接和bundle配置见[部署手册](../DEPLOYMENT.zh-CN.md#4-dsh接入)。

打包方式：在完整源码目录运行`npm pack --ignore-scripts`生成`dsh-ensp-fusion-1.1.1.tgz`。安装到**实际使用的profile**，以下仅以desktop及示例路径说明：

```powershell
dsh plugin --profile desktop add "C:/tools/dsh-ensp-fusion/dsh-ensp-fusion-1.1.1.tgz"
```

该版本CLI将包操作转交pnpm。保留profile的其他依赖及配置；已启用的`dsh-ensp-fusion` bundle保持原设置，首次接入按部署手册合并bundle。安装后重新加载插件；如进程仍持有旧模块，再重启DSH。不要继续导入旧`1.1.0.tgz`或旧GitHub标签。npm尚无本包，不能用公开registry安装命令替代本地修复包。

本轮修复没有修改用户profile；检查时本机profile中没有已安装的`dsh-ensp-fusion`依赖，因此不能声称活动桌面会话已自动替换旧版本。
