# 源码融合设计

## 来源与取舍

| 来源 | 复用能力 | 融合方式 |
| --- | --- | --- |
| YunoSeng/dsh-ensp | GUI、控制台、拓扑编辑、文档流程 | 经ENSPLB增强实现接入 |
| ENSPLB | 会话错误处理、保存确认、就绪检测、只读验收、计划生成 | 作为基础执行通道 |
| lizi600jin/dsh-ensp | 拓扑生成、解析、场景指导 | 在upstream保留源模块，通过适配层接入 |

统一包名dsh-ensp-fusion避免来源项目重名。index.js注册基础工具和融合工具，mcp/server.js复用注册，CLI使用同一工具处理器。

## 可靠性约定

- 配置批次预校验，逐命令检查失败，不自动回滚已生效配置。
- 保存需要成功回显，不能只将命令送达当作保存成功。
- 收敛等待复用VrpSession，避免第二套控制台实现。
- 生成器校验设备、端口、接口、路径并拒绝覆盖。
- GUI通过独立Windows侧车执行，具有事务、窗口归属及超时保护。
- 只读验收通过明确断言输出结果，和配置生成计划分开。

## 扩展边界

当前保持DSH/MCP/CLI三种入口，不实现独立仿真后端、远程多租户服务或Web管理界面。进一步开发可拆分base.js、统一响应结构、扩展设备型号及版本化配置/验收模板。

需要自行审计来源时运行npm run audit:sources -- <ENSPLB目录> <YunoSeng目录> <lizi600jin目录>。目录由调用者提供，不预设维护者的源码布局。输出默认写当前目录source-audit.json，可用ENSP_AUDIT_OUTPUT指定；审计产物可能包含来源仓库元数据，应保存在独立工作区，不随插件分发。
