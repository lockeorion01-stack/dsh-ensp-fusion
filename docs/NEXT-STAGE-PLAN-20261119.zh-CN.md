## 3. M2.1：先补齐稳定性与运行基线

### A1：诊断结果输出契约（P0）

目标：诊断在失败场景下也能返回可校验、可追踪的结构化证据。

实施步骤：

1. 使用隔离候选复现 E1，记录返回值路径、运行入口和构建指纹；不以旧日志代替当前复现。
2. 沿诊断结果生成、公共结果封装、DSH/MCP 序列化边界定位违规字段；检查 undefined、非有限数、Error 实例、循环引用等可能性，不预判根因。
3. 在产生结果的边界修正明确字段；缺失与未知按契约表达，不通过 JSON 往返或丢字段把失败伪装成功。
4. 保留已有公开字段与类型，必要的新字段版本化；DSH 错误信封、MCP isError 和 CLI 退出状态保持一致。

拟检查位置：lib/console-diagnostics.js、诊断工具注册/输出 schema、lib/tool-outcome.js、lib/operation-result.js、入口适配器。

验收：正常读取、无日志、设备未找到、权限拒绝、读取中变化、探测超时、取消、底层异常均可经真实宿主模块返回；错误分支保留失败/覆盖信息；定向测试中 lossless JSON 拒绝为 0。该“0”只约束验收矩阵，不宣称所有现场输入已穷尽。

交付：契约缺陷复现、字段修复、跨入口结果矩阵与回归样例。

### A2：GUI 全计划预校验和接口一致性（P0）

目标：可静态识别的参数错误必须在第一个有副作用的步骤前返回。

实施步骤：

1. 对全部受支持 op 建立统一字段定义，核对公开 schema、示例、JS 调度与 Python 执行器。
2. 整批检查必需字段、类型、范围、操作名、截图目标、快捷键结构、坐标参数及输出路径；错误返回步骤索引和字段路径。
3. 明确截图 out/path 策略：如兼容 path，则入口规范化一次；两个参数冲突时拒绝，不静默选择。以当前公开契约为兼容基线。
4. 将静态预校验与执行前动态守卫分开：窗口句柄、PID/创建时间、前台归属、模态框及几何状态仍在输入前重新检查。
5. 中途失败保留已执行/未执行步骤及 may_have_applied，不自动从头重跑整批。

拟检查位置：base.js 中 GUI 注册与调度、lib/bridge-client.js、lib/bridge.py 及现有 GUI 测试；仅在实现阶段按最小责任提取校验模块。

验收：缺 out、缺 x、未知 op、非法 key/mods、无效路径等矩阵均返回结构化错误；前置无效批次的模拟输入发送计数为 0；焦点被 WPS 等窗口占用仍拒绝输入；合法旧调用保持兼容。

交付：操作字段清单、整批预校验、兼容说明及无输入回归证据。

### A3：控制台状态与重复调用收敛（P1）

目标：根据终端当前状态推进，不依靠重复登录、重连或重复发命令碰运气。

拟统一状态：未连接、连接中、启动中/非 VRP、待认证、待交互、VRP 就绪、身份不符、失败、状态未知。状态命名和返回位置在实现前核对现有字段，优先复用，不覆盖旧 outcome/failure。

| 状态 | 允许的后续动作 | 停止条件 |
| --- | --- | --- |
| 连接拒绝/启动中 | 在单调总截止时间内有界退避探测 | 预算耗尽或出现明确失败 |
| 待认证 | 使用本次明确提供/引用的凭据完成一次认证流程 | 明确认证失败；不猜密码、不循环提交 |
| 待交互 | 检查当前提示，并在身份/提示匹配时提交明确回复 | 没有匹配回复、提示改变或取消 |
| VRP 就绪 | 核对目标、视图和命令能力后发送 | 身份/视图不符 |
| 状态未知/可能已执行 | 只读核验和取证 | 不自动重放配置、save 或启动动作 |

设备会话身份应结合拓扑路径/UUID、设备名和控制台端口；共享锁、状态缓存和冷却标记均有容量/过期策略，重连后重新确认身份。恢复后的明确新状态应允许正常操作，不能永久拉黑端口。不要把以 ## 或 # 结尾的未知输出直接判为 VRP 提示符。

拟检查位置：lib/cli.js、lib/device-ready.js、lib/device-execution.js、lib/console-diagnostics.js、既有设备锁与 M2 执行控制。

验收：固定待交互/认证失败场景不再产生无进展的认证或配置发送；连接就绪后可以推进；所有等待受总截止时间约束；取消后不再发送新命令；无身份匹配时不复用旧会话结论。记录被抑制的重试及原因，不能只靠降低日志级别“消除错误”。

### A4：编排成功判据和受维护示例（P1）

复用 M1 的 normalizeOperationResult / assertOperationSucceeded。审查仓库维护的技能、注入指导、run_code 示例和验收脚本，移除“catch 后无条件 ok:true”及“不抛异常即成功”的判据；保留必要的部分成功汇总。用户归档脚本不直接改写。

明确区分脚本执行完成、工具动作完成、GUI 投递、命令观察、保存、磁盘持久化、重开和业务验收。涉及多个必需子项时，汇总必须保留失败、跳过、未知和证据引用，不能把任一层自动升级成下一层成功。

验收：预置一个子设备失败、GUI 中途失败、结果未知及显式业务断言失败，均不能得到整体业务通过；原始 CLI output 中的 JSON 文本不会被当成工具返回契约递归解释。

### A5：候选发布与运行基线核验（P1，M3 现场前置）

复用 scripts/check-installed.mjs、check:dsh 和 ensp_status 构建回读能力。顺序为：新候选打包 → 包外内容清单 → 隔离解包核验 → 安装目录对比 → 宿主模块验证 → 明确切换窗口 → 运行会话回读。每层独立报告，不以版本号或 Electron-as-Node 成功替代实时桌面验证。

实施时先完成可审查候选、完整包备份和回退步骤，再按用户已授权范围安排运行副本切换；本规划本身不触发重启或部署。缺少实时回读时标记 runtime_unverified，不伪造通过。回退以完整旧包为单位，并再次回读指纹；不覆盖零散文件。

验收：同版本不同内容、安装目录已更新但进程仍加载旧代码、缺少/陈旧回读、候选文件缺失均有明确结论。下一次现场实验必须记录 root/fingerprint/loadedAt、采集时间和入口。

## 4. M3：生命周期与持久化验证

M3 复用总方案 W6/W7，以下细化任务拆分与证据要求。现场入口门禁：A1/A2 完成或候选确认已修复；A3/A4 回归通过；A5 能识别并记录实验实际加载构建；存在独立工程副本和可核验回退材料。

### B1：受保护的生命周期计划（P1 / W6）

新增生命周期编排器，优先接入现有验收 CLI 的显式计划入口；不增加第 20 个工具，不改变低层 GUI 快捷操作的默认含义。拟新增位置为 lib/lifecycle-runner.js，复用 topology 预检、原生启动参数预检、device-ready、project-checkpoint、change-journal、recovery-guard 和 M2 执行控制，不另造锁或恢复机制。

计划必须声明：工程绝对路径与身份、设备拓扑 UUID/名称/端口、运行构建、阶段选择、总预算、明确的配置/保存/停止/重开动作、预期检查、证据目录。新计划字段和 CLI 参数属于待实现设计，不能将本段作为当前可执行接口。

状态按依赖推进：

IDENTIFIED → PREFLIGHTED → CHECKPOINTED → STARTING → READY → CONFIGURED → SAVED → DISK_VERIFIED → REOPEN_VERIFIED → BUSINESS_VERIFIED。

各阶段单独记录 pass / fail / inconclusive / not_requested；这属于阶段验收记录，不替换 M1/M2 的 execution.status 枚举。无配置、无重开等可选阶段必须标 not_requested，不能标通过。任何必需阶段失败或未知，停止其依赖动作；中断后先只读重建状态，不自动从最后一步续发命令。

| 阶段 | 核验内容 | 放行依据 |
| --- | --- | --- |
| IDENTIFIED | 磁盘工程与当前 GUI 目标、拓扑 UUID 和进程身份 | 有可审查的当前工程身份；仅文件存在或同名标题不足以确认 |
| PREFLIGHTED | 参数、镜像、原生组件启动参数、输出路径、动作权限与总预算 | 所有必需前置项通过，未知项明确阻塞 |
| CHECKPOINTED | 复用稳定性检查，备份放在工程目录之外 | 清单、哈希及 stable:true；不稳定检查点不可用于恢复 |
| STARTING / READY | 首版启动组大小为 1，逐台确认后推进 | VRP 设备为身份匹配的提示符与 display version；原生 Server/Client 用对应进程/参数和协议探测 |
| CONFIGURED | 仅发送计划中明确列出的配置 | 命令与必要断言均通过；已发送但未确认单列 |
| SAVED / DISK_VERIFIED | 设备保存、工程同步与磁盘预期内容 | 各层独立证据；save 回显不能替代磁盘验证 |
| REOPEN_VERIFIED | 正常停止并从独立副本的同一绝对路径重开 | 工程身份、设备身份与预期配置复核通过 |
| BUSINESS_VERIFIED | 使用明确的协议/业务断言 | 指定断言与样本通过，保留时间窗口和适用范围 |

默认单台分组是待测的保守策略，不是“九台阈值”的证明。全应用重启、系统依赖替换和全拓扑强停不作为失败后默认动作。GUI 发送前仍执行现有焦点、模态框和几何守卫。

验收：非法计划在动作前拒绝；阶段缺证据不放行；身份变化/取消后不发送后继动作；重开后错误工程、配置缺失和业务失败能够分别识别。

### B2：保存、同步与同路径重开证据（P1 / W6）

按“命令完成 → 设备保存 → 工程同步 → 磁盘检查 → 同路径重开 → 业务验证”逐层留证。对 current/saved/磁盘配置的比较采用明确的预期配置范围及有版本的规范化规则，忽略规则必须列明；不能以全量动态输出的简单哈希代替语义核验。

验收环境使用独立工程副本，覆盖 1 台 AR、1 台交换机、1 台 USG 和 1 对原生 Server/Client；各完成至少 3 轮正常停止/同路径重开。每轮保留运行构建、工程路径/身份、配置检查、同步日志覆盖、协议结果和失败原因。不存在的能力标不适用，不伪造 VRP 检查用于原生 PC。

出现同步失败、配置差异或新崩溃签名即停止该场景后续轮次，保全当前证据；修复后新建运行编号复测，不能用后续成功覆盖失败历史。只有重开核验通过才能写 reloadVerified:true。仅回滚插件包不会回滚设备配置；设备恢复只能使用计划中明确选择且 guard 校验通过的动作。

交付：生命周期计划 schema、样例计划、每阶段 evidence_refs、逐轮结果矩阵及未通过项。

### B3：只读并发、资源上限与测量（P1 / W7）

范围限于独立设备的已准入就绪查询和只读取证。配置写入、save、交互回复、GUI 输入和未知影响命令维持串行；同一端口仍只有一个会话。复用 W1 命令影响分类与 M2 截止时间/取消链路。MCP 的 isConcurrencySafe:false 保持。

readiness_concurrency 拟默认 1，独立验收台显式试用 2，首版上限 2。基准使用固定镜像、宿主资源和 1/5/10 台设备组合，每个并发设置至少 5 轮；设备启动仍按 B1 串行计划，不能将“10 台就绪查询”解释为“一次启动 10 台”。配置不足时缩小矩阵并说明，不能伪造数据或外推容量。

记录总时长、各设备耗时、中位数、成功/失败/未知分类、CPU/内存采样、桥启动次数和新异常事件。小样本百分位数只作描述，不作为稳定容量保证。

并发 2 的试用放行标准：样本内无锁冲突/命令串线，原通过场景仍通过，就绪检查总时长中位数改善至少 15%，无新相关异常签名。未满足则维持 1；达到门槛也只适用于已测组合，不直接升级所有用户的默认值。

资源边界同时核查：resident 最大响应帧初始目标 4 MiB，具体值由现有最大合法响应确认；任务映射、socket、监听器及临时文件均有上限和终态清理规则。执行 500 次离线取消/失败注入后，检查资源数量回到可解释基线；活动或终态未知任务不得仅因文件年龄被删除。

交付：可复核基准数据、资源泄漏检查、并发准入结论与默认值决策。

### B4：原生崩溃证据闭环（P2，现场验证期间持续）

复用 M1 incident 收集器，在明确时间窗口和工程范围内关联 Application 1000/1001、WER、Client/PCServer/VBoxServer 日志及操作元信息。归档历史事件与本次现场采集分开标识，分别保留原始记录数、可确认进程实例数和无法归组数量。

优先补齐通道/RecordId、应用路径、PID/进程创建时间、模块版本、报告标识及时间来源。时间相邻仅记 temporal_only，同进程仅记 same_process；都不升级为因果。可读的既有 dump/调用栈按明确对象单独调查，缺失时给出缺口，不把异常码本身当成源码定位。

控制实验在独立工程中一次改变一个因素：手工查询、插件单设备查询、额外文件导出、额外 GUI 回显分别记录。新异常一旦发生，保全现场并停止相应实验。九台阈值不作为故意反复崩溃的目标；系统 DLL/VirtualBox 版本替换或启用新的 dump 捕获另列具体排障方案。

交付：异常签名清单、coverage、操作时间线、可支持/不可支持的结论和后续定位所需材料。
