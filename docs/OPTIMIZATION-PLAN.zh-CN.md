## 4. W1：统一结果契约，防止包装脚本掩盖失败

### 具体改动

新增 `lib/operation-result.js`，提供 `normalizeOperationResult(toolName, result)` 和 `assertOperationSucceeded(toolName, result)`；`lib/tool-outcome.js`、`mcp/server.js`、`bin/ensp-fusion.mjs`、验收器及原生服务恢复统一使用。`operationOk` 保留为兼容导出，内部委托公共判定器。通过 `package.json` 增加 `dsh-ensp-fusion/result` 导出，使受维护脚本能够引用断言函数；入口适配器负责按已知格式拆宿主信封，公共判定器处理工具业务结果。

采用**按工具声明的结果路径**识别必需项，例如 CLI 的设备、命令和断言，GUI 的 steps，fusion 工具的 `data.ok`。不递归搜索任意正文中的 `ok:false`，不将原始命令输出当 JSON 反复解析。JSON 字符串只在已知 `data` 边界有界解析一次；格式异常保留原文类型并记录无法判定。

在不覆盖旧 `status`、`outcome` 等字段的前提下新增：

```json
{
  "ok": false,
  "execution": {
    "schema_version": 1,
    "operation_id": "<uuid>",
    "status": "partial",
    "operation_verification": "unconfirmed",
    "business_verification": "not_requested",
    "may_have_applied": true,
    "failed_paths": ["devices[1].results[2]"],
    "skipped_paths": ["devices[2]"],
    "evidence_refs": []
  }
}
```

| 新状态 | 含义 | 聚合成功判定 |
| --- | --- | --- |
| `success` | 当前工具所承诺的动作已成功；GUI 可能仅承诺投递 | 可为 true；必须另读验证层级 |
| `failed` | 明确失败且没有需要单列的已完成部分 | false |
| `partial` | 至少一项完成，同时存在失败或未完成的必需项 | false |
| `inconclusive` | 证据缺失、未知格式或无法完成判定 | false |
| `cancelled` | 已确认中止，后续动作未再发送 | false |
| `unconfirmed` | 请求可能已执行，但终态未确认 | false |

`operation_verification` 为 `confirmed / dispatched / unconfirmed`；`business_verification` 为 `pass / fail / inconclusive / not_requested`。GUI 投递成功允许维持已有 `ok:true`，同时必须保留 `dispatched`，不得被包装脚本升级为工程打开、配置保存或业务通过。`assertOperationSucceeded` 检查操作成功；业务验收必须使用业务判定器另行检查。

若已知必需子项失败，即使外层原为 `ok:true`，聚合也改为 false。DSH、MCP 均标记工具错误，CLI 退出 1；成功仍退出 0。DSH 的错误信封继续遵守 SDK 契约，将完整脱敏结果放入 content，不能为了返回旧 value 而伪装成功。

### 命令影响分类

新增 `lib/command-effects.js`。现有 `isReadOnlyCommand` 把 `save`、`reset counters`、`refresh` 等也列入“只读”，目前用于自动保存和失败提示。它不能直接成为未来并发准入、自动重试或可重放判断依据。

将“是否修改运行配置”“是否修改持久化状态”“是否改变会话/计数器”“是否生成流量”分开记录。未知命令标为 unknown；`display` 也只接受明确查询形态，不因前缀匹配就授权自动重放。`ping/tracert` 归主动探测，`save` 归持久化，`reset counters` 归状态变更，`system-view/quit` 归会话控制。

第一步保持旧自动保存策略，通过单独的兼容函数表达；新分类用于证据和 W7 准入。后续如调整保存默认值，另行提供迁移说明。给 `run_code` 示例提供公共断言用法，删除吞异常后返回空字符串、按“不抛异常”计成功的示例。

### 验收

跨 DSH/MCP/CLI/验收器验证：对象/字符串 `data.ok:false`、第二设备失败、断言失败、跳过、未知格式、GUI 仅投递、明确业务失败。要求预置失败样本无一误报成功；成功响应的旧字段及类型保持兼容；不改写其他插件的结果。

## 5. W2：统一关联 ID 和执行证据

新增 `lib/operation-context.js` 与 `lib/execution-events.js`。每次调用创建独立上下文，通过参数显式传递，不把并发请求的状态写入共享 `registry.exec`。

上下文包括 `operation_id`、`parent_operation_id`、可用时的宿主 `call_id`、入口、工具名、阶段、目标身份引用、构建指纹、墙上时钟和单调耗时。控制台记录端口与拓扑 UUID；GUI 记录 HWND、PID 和进程创建时间；不能仅按设备名或复用 PID 关联。

统一阶段事件：`started → validated → dispatched → observed → finished`，以及失败、取消请求、停止确认。动作发出前先写必要台账；记录发送与观察的区别。原生操作无法携带 ID 时，只提供带置信依据的旁路关联。

建议元信息记录默认开启，位于 `%LOCALAPPDATA%/dsh-ensp-fusion/diagnostics`，可配置目录或关闭；关闭后仍返回内联 `execution`。不默认记录完整参数、命令正文、配置、认证回复或会话全文。详细证据由显式取证/验收操作产生，沿用已有脱敏器。

建议上限：单条元信息 16 KiB、单个轮转文件 8 MiB、常规元信息总计 128 MiB、保留 7 天。按已关闭的普通记录清理，不自动删除活动任务、恢复台账或显式验收产物；受保护内容阻碍清理时停止新增详细记录并报告。Windows 文件权限使用适当 ACL，不把 POSIX mode 当作访问隔离保证。

普通可选追踪写入失败报告 `evidence_persisted:false`，不改变已确认的设备操作事实；要求证据持久化的验收任务则不能通过。写入错误不能触发动作重放。

验收覆盖凭据及其回显、嵌套 JSON、两个并发调用不串 ID、写盘失败、轮转、活动记录保留。执行耗时必须来自单调时钟，日志时间注明来源和未验证的时钟偏差。

## 6. W3：本机崩溃采集与关联报告

### 入口及实现

首期增加现有 doctor CLI 的 `incident` 子命令，保持无子命令时原有环境检查行为；不增加第 20 个工具，也不改变现有 `ensp_diagnose output` 的离线文本分析语义。

以下为**拟新增命令**，当前版本不可执行：

```powershell
ensp-fusion-doctor incident --from "2026-11-18T22:25:00+08:00" --to "2026-11-18T22:40:00+08:00" --workspace "F:/labs/ensp" --output "incident-20261118-2233" --session "C:/path/to/session.zst"
```

拆为 `lib/crash-collector.js`（限额、汇总）、`lib/windows-events.js`（事件 XML 读取与字段解析）、`lib/incident-correlator.js`（去重和关联）、`lib/incident-report.js`（脱敏产物）。Windows 事件查询使用无配置文件的 PowerShell、结构化过滤及 XML 字段，避免依赖本地化 Message 文本和拼接用户脚本。

### 采集范围

| 来源 | 采集内容 | 边界 |
| --- | --- | --- |
| Windows Application | 与三类 eNSP 应用及已知 DSH 宿主匹配的 1000/1001 事件 | 同时核对 Provider、应用路径和字段；缺字段保持未知 |
| eNSP 共享日志、UUID 匹配的 VM 日志 | 同步、串口、启动、退出等待错误 | 共享日志不强行归因设备 |
| PCServer 日志 | UTF-16LE BOM、网络及插件异常线索 | 独立解析，不能直接复用仅适合共享日志的解码规则 |
| W2 执行记录 | 操作、阶段、构建、进程身份 | 只能关联实际采集到的操作 |
| 显式指定的 DSH 会话 | 直接调用及引用记录、会话继承去重 | 不默认扫描全部用户会话；`run_code` 引用不冒充内部调用 |
| 可读 WER 报告 | 已有报告标识、模块、可访问证据路径 | 不修改 ACL，不自动配置 dump，不自动复制 dump |

默认最近 2 小时，显式范围最多 7 天；事件最多 2,000 条，日志最多 128 个文件，每个普通日志采样尾部 256 KiB，文件内容读取/解压总预算 32 MiB，总采集预算 20 秒。DSH 压缩日志逐帧流式解码，不对压缩文件任意截尾；达到预算就停止，报告 partial coverage。事件与报告输出也有独立字节上限，防止子进程输出无界增长。上述值均为待实现的初始限额，测试后只通过配置范围调整。

### 去重与判定

- 事件原始记录按通道和 RecordId 标识；应用名、PID、进程创建时间完整时才合并为同一异常实例，缺字段使用明确的低置信分组，不猜测创建时间。
- 事件 1001 按报告标识关联；保留原始记录数、可确认实例数及无法归组数，不把重复报告累加成独立终止次数。
- 先匹配进程身份，再匹配操作时间区间和可配置前后窗口（建议各 120 秒）。时间接近单列为 `temporal_only`，进程身份匹配列为 `same_process`；二者均不宣称因果。
- 保留本地日志时间、UTC 标准化结果、时区来源和时钟不确定性。mtime 仅供文件筛选，不能冒充事件发生时间。
- 没有匹配错误只能返回“样本未发现”，来源缺失、拒绝访问、达到限额或解析失败必须出现在 coverage 中。

### 交付与验收

输出新目录中的 `summary.json`、`timeline.jsonl`、`report.md` 和 `sources.json`；清单记录读取/省略数量、解码、错误及证据哈希，不覆盖原始日志。默认导出脱敏元信息与必要摘录，配置正文仍可能含未识别敏感信息，详细原文需显式选择。

固定回归包括：同 PID/同创建时间多事件、PID 复用、重复 WER、无法访问来源、UTF-16LE/GB18030、损坏压缩帧、超限、时区不明及只有时间关联。经脱敏的现场样本应保留原审计的异常分组规则；限额下统计减少时必须能由 coverage 解释。全量 73 实例的重放使用显式多批范围，不要求默认 2 小时采样覆盖全历史。

### 三类原生异常的排障路径

这部分用于 M1 之后的现场根因调查，不把收集器开发估算当作原生问题解决时限。

| 对象与已有线索 | 受控验证方式 | 推进条件与交付 |
| --- | --- | --- |
| Client：最新 KERNELBASE/c000008c；附近有配置导出调用 | 在独立工程记录手工查询、插件单设备查询、查询加文件导出、额外 GUI 回显四种路径，逐项比较；每次固定设备与命令，分别记录操作和进程身份 | 一旦异常先保全现场，停止批量复测；取得匹配签名的 dump/堆栈后定位实际模块，不能凭时间相邻认定 CLI 导出是根因 |
| PCServer：UDP 插件 40000015；既往有启动参数缺值/重复 | 先执行现有原生参数预检，再在通过预检的副本核对实际启动参数、内容文件及 HTTP/DNS/FTP；坏参数仅静态测试，不为复现而启动损坏实例 | 区分参数被拒、业务失败和进程异常；通过预检后仍崩溃则保留模块版本、异常签名及调用栈，不宣称预检修复 DLL |
| VBoxServer：combase/c0000602；VBox52.dll 与备份不同 | 记录 eNSP、VirtualBox、兼容 DLL 的路径/位数/版本/哈希和可观测加载链；在独立环境一次只验证一个明确组合 | 先复现并取得证据，再提出兼容组合或替换方案；文件 mtime 和哈希差异只作为线索 |

若已有 WER 无可读 dump，再单独形成限定到目标进程的转储捕获与撤销方案，列明磁盘上限、触发条件和潜在敏感内容后实施。首次出现新的异常签名即暂停相应现场实验，保全现有证据；不通过循环强启或更换系统 DLL 搜索“可用状态”。

## 7. W4：部署与运行副本核验

扩展 `scripts/check-dsh-host.mjs`：支持实际解包的 `resources/app/dsh/node_modules` 和 app.asar 结构，优先显式路径与实际安装信息，避免固定猜测。继续分别报告模块验证、Electron 启动验证、运行会话验证；`EACCES` 必须保留为该层未通过。

新增 `scripts/check-installed.mjs`，接收预期发布内容清单、安装目录及可选的 `ensp_status` 原始回读文件。逐层输出：

1. 打包产物：文件清单、大小、SHA256、入口完整性。
2. 安装目录：内容与产物一致；不能只比较版本号。
3. 宿主模块：19 工具、2 skills、错误传播、卸载和兼容性门禁。
4. 运行会话：`build.root / fingerprint / loadedAt` 与目标副本一致。

缺少运行回读时标记 runtime 未验证，不自动重启宿主。发布清单的文件集合与指纹算法明确版本化，清单本身排除在自引用哈希之外；保持当前 build 模块在加载时捕获指纹的语义。

验收必须让“同版本不同内容”“旧进程仍加载旧根目录”“仅模块检查成功”分别产生正确的差异/未验证结论。部署操作和运行回读在实施阶段形成具体候选包后单独执行。

## 8. W5：让取消传到实际执行层

已确认的接线缺口：`runAcceptance` 向 `execute` 传入 signal，但 `bin/ensp-fusion-accept.mjs` 的 execute 回调未接收和转交；MCP 当前忽略 `notifications/cancelled`；桥和控制台多数接口依赖各自超时。外层取消不能据此证明底层停止。

### 具体改动

W2 上下文增加 `signal` 与单调 `deadline`；入口级预算向下收敛，每层预算取“自身上限与剩余总预算”较小值。清理可使用独立、明确的预算，但不得无限延长。

| 层级 | 变更位置 | 取消行为 |
| --- | --- | --- |
| DSH | 工具执行边界 | 读取宿主实际提供的 signal，不依赖未验证字段 |
| MCP | `mcp/server.js` | 按 request id 保存独立 AbortController，接取消通知，结束后释放映射 |
| CLI/验收 | `bin/ensp-fusion.mjs`、`bin/ensp-fusion-accept.mjs` | SIGINT/SIGTERM 转 signal，execute 显式转交上下文 |
| 控制台 | `lib/cli.js`、`lib/device-execution.js`、`lib/device-ready.js` | 不再发送下一命令/认证回复，关闭 socket，结束等待后释放锁 |
| job 桥 | `lib/bridge-client.js`、`lib/bridge.py` | 每任务取消标识与任务身份绑定，进入互斥区及各 step 前检查，保留终态 |
| resident 桥 | 同上 | 提供可独立响应的取消控制路径；只断开请求连接不能当作停止证明 |

取消不能撤回已发送的设备命令或 GUI 消息。已投递但无终态时返回 `unconfirmed, may_have_applied:true`；只有确认不再执行后才返回 cancelled。不能通过单纯 Promise.race 或提前释放锁制造“已停止”。

job watchdog 继续只约束自身桥任务。必要的进程终止仅能针对已核验任务身份的本任务辅助进程；resident 不因单个请求取消就终止承载其他请求的进程。无法及时中断的原生调用进入未确认状态，保留原有 watchdog 和互斥保护，不自动重发，也不启动争用同目标的 cleanup。

取消确认建议预算 2 秒；超过后如实返回未确认和仍有效的任务截止时间，后续查询终态。恢复 cleanup 继续使用既有显式计划、独立预算和 guard；未确认原动作停止时先停止冲突清理。

### 验收

用可阻塞模拟控制台/桥在连接前、命令间、GUI step 间、命令已发送未收到结果时取消。检查底层发送日志：确认取消之后新增命令/step 数必须为 0；检查 socket、定时器、事件监听器、请求映射、设备锁和互斥锁的终态。保留“动作已生效但响应丢失”场景，要求 unconfirmed 且无重放。

## 9. W6：分阶段启动、保存和重开

新增 `lib/lifecycle-runner.js`，优先作为现有验收 CLI 的显式 lifecycle 计划入口，不改变低层 GUI 工具的既有快捷操作。复用 topology/原生参数预检、设备就绪、检查点、变更台账及恢复 guard。

生命周期按状态推进并落盘：

`IDENTIFIED → PREFLIGHTED → CHECKPOINTED → STARTING → READY → CONFIGURED → SAVED → DISK_VERIFIED → REOPEN_VERIFIED → BUSINESS_VERIFIED`

每个状态附证据和适用条件；不需要配置或重开的计划可跳过相应阶段，但必须标为未请求，不能写成通过。任一必需阶段失败就停止依赖动作，保留 partial/unconfirmed。重启宿主后只读重建已知状态，不自动续跑原动作。

关键规则：

- 操作前确认工程身份。磁盘拓扑清单不能证明当前 GUI 正在使用该文件；不能确认时停在 IDENTIFIED/未确认，列明缺失证据。
- 启动采用显式分组，按轻量设备、USG、原生 Server/Client 的计划顺序执行。默认每组 1 台，确认就绪后再推进；后续根据 W7 数据开放更大组。
- 就绪要求提示符与真实 `display version`；认证失败或仅 `#` 是终止条件，不追加盲等或猜测认证。
- 保存顺序为设备成功回显、预期 saved/current 内容、工程同步和磁盘内容、同路径正常停止/重开后的真实配置。只有重开验证通过才填 `reloadVerified:true`。
- 停机、保存、重开均由计划明确选择。临时配置允许保持未保存，并标明停机后影响；不能在取证流程中顺手 save。
- 对配置同步失败先保全检查点，完成单设备复现；不因 1,200 条重试消息自动重启全部 VM。
- 自动恢复只执行计划中已有且通过 guard 的恢复动作，身份/配置不符即停止。全应用重启、兼容 DLL 替换、VirtualBox 调整和系统 dump 配置分别作为独立排障动作评审。

实机验收使用独立工程副本，覆盖 1 台 AR、1 台交换机、1 台 USG 和 1 对原生 Server/Client；各完成至少 3 轮正常停止/同路径重开。检查真实 VRP、预期配置、同步日志和实际协议结果。记录失败轮次，不以重试成功覆盖；该结果只适用于验证过的镜像和组合。

## 10. W7：先测量，再开放有界并发

首期只优化 `lib/device-ready.js` 的独立设备查询和明确支持的只读取证，不并发配置写入、不并发 GUI、不改变 CLI 默认逐设备及首败停止顺序。W1 的命令影响分类是准入前提，不能使用旧“只读”正则授权。

新增就绪检查选项 `readiness_concurrency`：默认 1，独立验收台可显式试用 2，首版上限 2。保持同一端口只有一个会话；认证终止状态不重试；所有 worker 共享截止时间与取消信号。MCP 现有 `isConcurrencySafe:false` 保持，内部有限并发不等于允许客户端任意并发调度。

基准使用固定镜像、资源配置与设备组合（1/5/10 台；包含快启设备和 USG），每个并发设置至少 5 轮，记录总时长、各设备耗时分布、失败分类、采样的宿主 CPU/内存、桥启动次数及新异常事件。样本量小时不把百分位数当稳定容量结论。

并发 2 的试用门槛：在全部样本中没有锁冲突/命令串线，原本通过的场景保持通过；启动时间中位数改善至少 15%，且没有新的相关异常签名。未满足则维持默认 1，并保留测量报告；小样本无新异常不证明长期无崩溃。

补充资源控制：resident 响应设置最大帧长度（初始建议 4 MiB，超限明确失败）；job/status 文件按任务终态清理，活动或结果未确认文件不按年龄盲删。500 次离线取消/错误注入循环后检查辅助进程、连接、监听器和临时文件是否回到可解释基线。
